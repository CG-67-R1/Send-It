### HeadlinesSettingsScreen *(modified)*
- [P1] **Track Arrival toggle does not handle the "user denied then retries" case after dismissing the Settings deep-link.** `handleTrackArrivalToggle` checks `requestForegroundLocationPermission()` only at enable time. If the user taps Settings, grants, returns to app, and re-toggles, a second `requestForegroundPermissionsAsync()` call will resolve `granted` immediately — this is fine. However if the user navigates back without granting, the switch stays `false` but the UX shows no retry affordance — minor gap, acceptable as P2 downgrade candidate.
- [P2] The "Track arrival reminders" toggle is placed inside the existing **Notifications** section with a single leading subtitle explaining push Priority-1 news; the track-arrival subtitle appears after the P1 toggle, which makes the section read as if both switches relate to notifications. Would be clearer as a separate "Reminders" section.

### CalendarScreen
- [P2] No new issues. 107 events aggregated locally, 104 on production.

### QAScreen *(unchanged code, latent issue)*
- **[P0] `expo-firebase-analytics` imported and called (4 call sites), no Firebase project configured in repo.** No `google-services.json`, no `GoogleService-Info.plist`, no `firebase` config in `app.json`. In Expo Go this may silently fail; in a standalone EAS build it will likely throw a native module linking error or crash at startup. The `Analytics.logEvent()` calls are **not wrapped in try/catch** at all 4 sites (lines 190, 226, 248, 286) — a runtime throw here would surface as an unhandled rejection during trivia play.
- [P1] (Carried from 2026-07-13) No rate limiting on `/roadrace-ai/*` endpoints — OpenAI cost exposure still open.

### RiderCoachScreen *(modified)*
- [P1] **`seedDraftMessage` route param is never reset after use.** `RiderCoachScreen` sets the input from the param, but when the user navigates away and returns (without a new arrival event), `route.params?.seedDraftMessage` persists in React Navigation's param state. The `lastDraftKeyRef` guard prevents re-injecting the *same* draft, but if the user clears the input and navigates away/back, the draft will re-appear because `params` was never reset to `undefined`. **Correct fix:** call `navigation.setParams({ seedDraftMessage: undefined })` after consuming the draft (common React Navigation pattern).
- [P2] `getParent()` cast `as { navigate: (name: string, params?: object) => void } | undefined` (TrackArrivalOverlay line 86) is a loose cast that bypasses type safety — use typed navigator or `useNavigation<BottomTabNavigationProp<TabParamList>>()` instead.

### TrackWalkScreen *(modified)*
- [P2] `recheckArrival()` called in `useFocusEffect` (line 108-109) triggers a location check every time the user focuses the tab. This means a GPS call fires on every tab visit, even if the feature is disabled. `checkTrackArrival()` does short-circuit if the feature is disabled (reads AsyncStorage) so it won't show an unwanted banner, but the AsyncStorage read + guard still fires on every focus — minor battery/IO overhead.
- [P2] No visual indicator when "Send to Coach" succeeds in TrackWalkScreen (navigates + clears state silently).

### ImportTrackNotesScreen
- [P2] No new issues. Track context, paste, and send-to-coach flows intact.

## New feature audit — Track Geofence + Arrival

### `catalog_track_geofences.json`
- 10 Australian circuits with 1 km radius geofences. Correctly switched from `.geojson` to `.json` for Vercel static bundler compatibility.
- `trackGeofenceMatch.ts` falls back to `catalog?.name ?? feature.properties.name` — good defensive coding.
- `getTrackById()` from `tracks.ts` is called per-match; if `trackId` in the geofence catalog does not match `tracks.ts` IDs exactly, name resolution silently falls back to the catalog name (acceptable).

### `trackGeofence.ts`
- `checkTrackArrival()` correctly gates on `isTrackArrivalEnabled()` first. 
- Snooze uses 48-hour window stored as ISO string — sensible.
- No timeout on `Location.getCurrentPositionAsync` — if GPS is slow this call can hang indefinitely before resolving or throwing. `AbortSignal.timeout` is not available for expo-location; recommend `timeoutInterval` option or a `Promise.race` with a timeout.

### `TrackArrivalOverlay.tsx`
- **[P1] Navigation to RiderCoach uses `navigation.getParent()` with a loose runtime cast** — if overlay is rendered inside a stack navigator deeper than expected, `getParent()` may return the wrong navigator. The overlay is mounted inside `TrackArrivalProvider` which wraps `MainTabs`; `navigation.getParent()` from within the `NavigationContainer` root will be `undefined` since `TrackArrivalOverlay` is not itself inside a navigator screen. **This will silently fail to navigate** — `tabNav?.navigate(…)` is guarded by `?.` so no crash, but tapping "Open coach" does nothing visible to the user other than dismissing the banner.
  - Root cause: `TrackArrivalProvider` renders `TrackArrivalOverlay` as a child of the `NavigationContainer` but *outside* any `Navigator` — `useNavigation()` inside `TrackArrivalOverlay` will throw `Cannot use 'useNavigation' outside a navigator` in development, or silently return a stale ref in production.
  - **Verify immediately on device** — this may completely break the primary CTA of the new feature.
- `checkingRef` prevents concurrent GPS checks — good.
- Banner dismisses with `dismissedSessionRef` per-session (non-persistent) — correct.

### `trackWeather.ts`
- Calls Open-Meteo — no auth required, good. 8-second `AbortSignal.timeout` present.
- No retry logic; a single network failure silently returns `null` and the banner shows "Conditions: (empty)" — acceptable graceful degradation.

### `arrivalCoachDraft.ts`
- Clean, pure function. `Intl.DateTimeFormat` uses `undefined` locale (device locale) — correct.

## Cross-cutting

### Navigation
- `getParent()` pattern used in 4 places (`TrackArrivalOverlay`, `HeadlinesScreen`, `ImportTrackNotesScreen`, `TrackWalkScreen`). These are fragile: a navigation hierarchy change breaks all of them silently. Recommend defining a typed `RootNavigationRef` and using `rootRef.current?.navigate(…)` — one refactor fixes all 4 sites.
- `TrackArrivalOverlay` uses `useNavigation()` outside a Navigator screen — likely broken (see P1 above).

### AsyncStorage key management
- New keys: `@roadrace_track_arrival_enabled`, `@roadrace_track_arrival_state`. Both documented in `trackGeofence.ts`. No migration needed (additive).
- Total named keys is growing — recommend a `STORAGE_KEYS` constants file to prevent future collisions.

### Permissions
- Location (foreground): `HeadlinesSettingsScreen` requests permission and provides a Settings deep-link on denial — good UX.
- `requestForegroundPermissionsAsync()` in `trackGeofence.ts` returns the OS dialog; no `expo-location` config plugin entry check was done — verify `app.json` has `expo-location` in plugins with `locationWhenInUseUsageDescription`.

### API / offline
- All network calls use `AbortSignal.timeout` (except `Location.getCurrentPositionAsync`). Good.
- Open-Meteo weather call from within `TrackArrivalOverlay` fires on every banner display — acceptable.

### Sentry
- Lazy-loaded in `App.tsx` with `EXPO_PUBLIC_SENTRY_DSN` guard — no DSN in repo, zero-config in dev/Expo Go. Correct pattern.
