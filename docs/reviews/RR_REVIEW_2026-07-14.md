  second toggle is GPS-based. Low priority — cosmetic; suggest separate "Reminders" section.

### CalendarScreen
- No new findings. 107 events locally, live API cold-started this run.

### QAScreen *(P0 resolved)*
- [RESOLVED] Direct `expo-firebase-analytics` import replaced with `logAnalyticsEvent()`
  from `analytics.ts`. All 4 call sites updated to `void logAnalyticsEvent(...)`.
- [P2 — new] The `analytics.ts` wrapper does `await import('expo-firebase-analytics')`.
  If the native module is not linked (Expo Go, web, or builds without Firebase), the dynamic
  import itself throws — correctly caught by the outer try/catch. However if `Analytics.logEvent`
  throws for any reason other than missing module (e.g., invalid param type), the error is also
  silently swallowed. This is acceptable defensive coding but means analytics failures are
  completely invisible. Consider a `__DEV__` console.warn on the catch for visibility during
  development: `catch (e) { if (__DEV__) console.warn('[analytics]', e); }`.
- [P1 — carried] No rate limiting on `/roadrace-ai/*` — **resolved in `ba382a5`**; see API
  section. Noting here for tracking completeness.

### RiderCoachScreen *(P1 resolved)*
- [RESOLVED] `navigation.setParams({ seedDraftMessage: undefined })` added after consuming
  the draft param. The `lastDraftKeyRef` guard was already present; the setParams reset
  ensures React Navigation state is cleaned so back-navigation does not re-inject.
- Confirm: `lastDraftKeyRef.current = draft` is set before setParams — correct order; the
  guard fires before params could be re-read.
- No new findings.

### TrackWalkScreen
- [P2 — carried] `recheckArrival()` fires on every `useFocusEffect` — this triggers an

  when disabled, but still an unnecessary IO round-trip. Low priority.
- [P2] No success feedback when "Send to Coach" completes (navigates silently). A brief

### ImportTrackNotesScreen

## Cross-cutting

### Navigation
- `getParent()` pattern **eliminated** from `TrackArrivalOverlay` — replaced with global ref.
- `getParent()` still used in `ImportTrackNotesScreen` (line 175) and `TrackWalkScreen`
  (line 381). These work because both are rendered inside stack navigators that sit inside
  the Tab navigator — `getParent()` correctly resolves to the Tab navigator. No regression.
  A future refactor to use typed `RootNavigationRef` would be cleaner but is not urgent.

### AsyncStorage keys
- New keys `@roadrace_track_arrival_enabled`, `@roadrace_track_arrival_state` are additive.
- Recommend a `STORAGE_KEYS` constants file as the key count grows (currently ~8+ named keys
  across 5+ storage modules).

### Permissions
- Location (foreground): `expo-location` plugin present in `app.json` with
  `locationWhenInUsePermission` — verified. Permission flow in `HeadlinesSettingsScreen`
  requests and deep-links to Settings on denial — good UX.
- Camera, photos, calendar, speech recognition all have plugin entries and denial paths.

### API / offline
- All network calls use `AbortSignal.timeout` or `Promise.race` timeout. No hanging calls.
- Open-Meteo (weather) has 8-second timeout. Fails gracefully to `null`.

### Sentry
- Lazy-loaded in `App.tsx` with `EXPO_PUBLIC_SENTRY_DSN` env guard. Zero-config in dev /
  Expo Go. Correct pattern. No DSN in repo.

### Firebase / `expo-firebase-analytics`
- Module is in `package.json` and installed. No `google-services.json` /
  `GoogleService-Info.plist` in repo. Calls now routed through safe wrapper. This means
  analytics events are silently dropped — acceptable for PoC. If Firebase is never intended,
  consider removing the dependency entirely to reduce native build surface. If it will be
  wired up, add config files before EAS build.
