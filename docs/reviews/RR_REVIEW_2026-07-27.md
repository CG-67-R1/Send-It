### BikeBalanceSetupScreen *(major new feature this cycle)*

- **[P1]** **Keyboard UX on small-screen devices**: `BikeBalanceSetupScreen` uses a plain `ScrollView` for a 13-field inputs tab with `TextInput` numeric fields. No `KeyboardAwareScrollView` (or `KeyboardAvoidingView` wrapping the scroll view). On physical iOS/Android devices, the keyboard may cover the lower input fields with no auto-scroll. This is a common React Native friction point for data-entry heavy screens.

  **Recommended fix (Cursor):**
  ```bash
  cd app && npm install react-native-keyboard-aware-scroll-view
  ```
  Or use Expo's `KeyboardAvoidingView` wrapper + `ScrollView` with `keyboardShouldPersistTaps="handled"` and `scrollIndicatorInsets`. The GEO_FIELDS tab also has 8 more fields — same risk applies.

- **[P2]** Tab switching (`inputs → results → compare → guide`) does not preserve the scroll position within each tab. A user who scrolls down to CoG fields, switches to Results, then back to Inputs will land at the top. Since the 4 tabs are rendered as a single conditional view (not a `TabView` with lazy mounting), each tab switch re-renders from scratch. For the engineer/tuner skill level targeted by this screen, this is UX friction.

  **Recommended fix (Cursor):** Wrap each tab's content in a separate `ScrollView` with a `ref` and `contentOffset` restored on tab focus, or use `react-native-tab-view` with `lazy` mounting. Alternatively, accept the current behaviour and add a "Jump to CoG" quick-scroll button for the lower fields.
