## Cross-cutting

**Dual-tree drift (P1).** `app/src` vs `android-app/src` differ in 5 non-asset files. The `constants/` and `App.tsx` diffs are empty; `api.ts` matches. Content differences:
- `QAScreen.tsx`: UK-only trivia region, `TRIVIA_USED_UK`, rulebook meta state. Android has none.
- `askChat.ts`: `RulebookMeta` type and `asRulebookMeta`. Android drops `rulebook` from the response. The API already returns `rulebook` in `/roadrace-ai/ask` (server.js).
- `storageKeys.ts`: `TRIVIA_USED_UK` missing on Android.
- `CalendarScreen.tsx`: missing the undated-event guard (see above).
- `src/assets/bike-setup/suspension-bike.png` (84 KB vs 340 KB) and `suspension-map.png` (177 KB vs 682 KB) differ in size. Android has the larger image. Decide which is intended and sync. The `home-poc-bike.png` files are also modified uncommitted in both trees.

Decision for Cursor: `releasePack.ts` and the `x-pack` header ARE mirrored in `android-app`, so drift in the UK-aware screen code looks like an oversight rather than a deliberate Android exclusion. Either mirror the changes or document why not.

**Navigation:** one typed `getParent()` in HeadlinesScreen; nothing else brittle found.

**Storage:** keys are centralised in `storageKeys.ts`. `TRIVIA_BEST_SCORE_KEY` is referenced in QAScreen separately from `STORAGE_KEYS` and should live with the others (P2). I did not check migrations.

**Permissions and device paths:** not exercised by code gates. See manual checks.

**API URL and secret:** `apiFetch` adds `x-app-secret` from `EXPO_PUBLIC_APP_API_SECRET`. That value is bundled into the client, so it is not a secret against anyone who extracts the bundle. It only deters casual abuse. The server warns when `OPENAI_API_KEY` is set but `APP_API_SECRET` is not. I did not inspect Render's env, so I do not know whether `APP_API_SECRET` is set in production (P2: verify).
