## Observed this week

| Site | First-screen order | How the product is shown | How the benefit is phrased | Store / primary action | Trust line near the action |
|------|--------------------|--------------------------|----------------------------|------------------------|----------------------------|
| Strava | Short value headline, one sentence on scale, sign-up buttons | Device frame with a real activity screen, one per feature block | Verb-led block headlines (record, analyse, explore), one benefit sentence each | Sign-up repeated after every proof block | "Free to join / free to use" sits directly under the final action |
| AllTrails | Search box over full-bleed photography, then three quick-action links | A phone body beside each benefit, one phone per feature | One short outcome sentence per phone (record, work offline, build a route) | QR code plus both store badges beside every phone | None on the first screen. Scale and reviews sit lower |
| TrainingPeaks | Audience split first (athlete / coach), each with its own action | Hero art and cards, product UI mostly deeper in | Names the athlete's goal ("first 5K to IRONMAN") before features | Free-trial link per audience | Trial length stated beside the button; device-partner logo strip as proof |

## Patterns worth applying (no new claims needed)

- Show a real phone screen per benefit block and repeat the store action after each, as Strava and AllTrails do.
- Put the free/limit line directly under the action, not at page foot (Strava, TrainingPeaks).
- Offer a QR code beside the badge for desktop visitors (AllTrails). Phone visitors tap the badge.
- Name the audience before the product name (TrainingPeaks audience split).
